四、本次实测结论与未覆盖项

  1) 依赖闭合：objdump -p 读取 lingya.exe 及四个 Qt 运行库的 PE 导入表，全部非系统依赖均在
     本清单内（含仅被 Qt6Core 间接导入的 libwinpthread-1.dll）。
  2) 部署自洽：在 PATH 仅含 C://WINDOWS//system32 的环境下启动，8 秒存活、无平台插件错误；
     QT_ASSUME_STDERR_HAS_CONSOLE=1 + QT_DEBUG_PLUGINS=1 的加载日志中，插件路径出现 staging
     目录 22 次、Qt 安装目录 0 次，证明未回落到 D:/Qt 内置前缀。
  3) 启动阶段实际加载的插件：platforms/qwindows、imageformats/qgif+qico+qjpeg、
     styles/qmodernwindowsstyle。tls/ 与 networkinformation/ 为按需加载，本次启动未触发。
  4) 未覆盖（不得据此宣告通过）：
     - tls/qschannelbackend 未经真实 HTTPS 请求验证（需真实密钥联网，属 M5 未过项 L-028）
     - 未在干净 Windows 机器验证（本项仅为本机精简 PATH 验证）
     - 未验证中文输入法、非 100% DPI、多显示器
     - windeployqt 提示缺 dxcompiler.dll/dxil.dll（D3D12 着色器编译器），Widgets 应用走
       D3D11/软件渲染，本次启动无影响；如后续启用 Qt Quick/RHI 的 D3D12 后端需补。
