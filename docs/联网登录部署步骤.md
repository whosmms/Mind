# 已有 Supabase 认证适配器部署步骤（H047）

H051 的右上角入口可先预览登录界面，项目正式使用的服务器等用户提供后接入。本页供维护者选择已有 Supabase 适配器时参考。

已有适配器提供 **Supabase 托管认证与本机工程文件**。由外部认证和邮件服务管理用户身份与邮件投递。客户端已接通注册、邮箱验证、登录、找回密码、记住登录和退出的适配器路径，真实项目及邮件投递有待配置后验收。

不需要租云服务器、不需要建用户表、不需要为工程配置对象存储。Supabase 管理认证用户，联网账号模块只调用 `/auth/v1/`。本轮不包含短信、第三方登录、MFA、改邮箱、账号注销或工程云同步。

## 1. 创建账号服务（维护者执行一次）

1. 打开 [Supabase 控制台](https://supabase.com/dashboard)，注册并登录，创建组织和新项目，例如 `lingya-mind-auth`。
2. 项目要求的数据库密码只保存在你自己的密码管理器；不要填进软件、聊天或仓库。本客户端不使用这个密码。
3. 等项目初始化完成，打开项目的 **Connect**，复制默认项目 URL，形如 `https://二十位项目编号.supabase.co`。当前客户端只支持这个默认 HTTPS 域名，不接受代理域名或自建实例。
4. 在 **Settings → API Keys** 创建或复制 **Publishable key**，以 `sb_publishable_` 开头。不要选 `sb_secret_`、`service_role` 或旧的 JWT `anon` 密钥。
5. 在 **Authentication → Sign In / Providers → Email**（面板版本也可能显示 Providers）启用邮箱注册/登录，保持 **Confirm email** 开启。密码最低长度设为 **12**；软件接受 12 至 128 个字符。保留邮件与认证限速，不把额度设为无限。

URL 和 publishable key 是客户端公开配置；数据库密码、secret key、SMTP 凭据是管理秘密。两种用途不能互换。[官方 API key 说明](https://supabase.com/docs/guides/getting-started/api-keys)

## 2. 配置发验证码的邮件服务

选用 **Resend SMTP**，由 Supabase 发邮件，桌面软件不接触 SMTP 密钥。需要一个你控制 DNS 的域名；已有域名可用 `auth.你的域名` 子域，不必部署网站。没有域名时，先在域名注册商取得一个，价格以购买页面为准；这不等于购买云服务器。

1. 注册 [Resend](https://resend.com)，进入 **Domains → Add Domain**，填自己的发信域名或子域。
2. 到域名 DNS 管理页面，逐项添加 Resend 当前页面给出的发信验证记录（名称、类型、值都照页面，不用示例值覆盖已有业务记录）；回 Resend 点验证，等待显示 **Verified**。只启用发信即可，不要求开通收信。
3. 在 Resend 的 **API Keys** 创建只用于该发信域名的发送权限密钥。该密钥只填下一步服务端 SMTP 密码框，不发给使用者，不放进客户端包。
4. 回 Supabase，进入 **Authentication → Notifications → Email → SMTP Settings**，启用自定义 SMTP，填写：

| 字段 | 值 |
|---|---|
| Sender name | 灵芽思维 |
| Sender email | `no-reply@你已验证的发信域名` |
| Host | `smtp.resend.com` |
| Port | `465` |
| Username | `resend` |
| Password | 第 3 步的 Resend 发送密钥，仅在控制台保存 |

保存后查看发信额度与认证限速是否满足人数；套餐和额度以当前控制台为准，不承诺免费无限使用。[Resend 官方接入步骤](https://resend.com/docs/send-with-supabase-smtp)、[域名验证说明](https://resend.com/docs/dashboard/domains/introduction)

Supabase 默认邮件服务只允许项目团队邮箱，普通使用者不能据此注册；不要为了测试让普通用户成为你的项目管理员。给队友或其他使用者发验证码前，应完成自定义 SMTP。[Supabase SMTP 限制](https://supabase.com/docs/guides/auth/auth-smtp)

## 3. 邮件改成数字验证码

在 Supabase 的 **Authentication → Email Templates**（也可能位于 Notifications → Email）修改下面两种模板。桌面软件没有网页回调，需要邮件显示验证码。

**Confirm signup**，主题：`灵芽思维：验证邮箱`，正文：

```html
<h2>验证灵芽思维账号</h2>
<p>请回到软件“联网账号 → 注册”，输入下面的验证码：</p>
<p style="font-size:28px;letter-spacing:4px"><strong>{{ .Token }}</strong></p>
<p>验证码有有效期，请尽快使用。若非本人操作，请忽略；不要把验证码提供给他人。</p>
```

**Reset password**，主题：`灵芽思维：找回密码`，正文：

```html
<h2>重设灵芽思维密码</h2>
<p>请回到软件“联网账号 → 找回密码”，填写验证码与新密码：</p>
<p style="font-size:28px;letter-spacing:4px"><strong>{{ .Token }}</strong></p>
<p>若非本人申请，请忽略。验证码使用后失效，不要提供给他人。</p>
```

两项分别保存。`{{ .Token }}` 是服务端替换的变量，保留原样；不要把某一次收到的验证码写入模板。无需设置网页回调或修改 Site URL 来配合本客户端。[官方模板变量说明](https://supabase.com/docs/guides/auth/auth-email-templates)

## 4. 在软件接入

1. 启动 H051 或之后的开发候选，选择 **文件 → 账号服务设置…**。
2. 填第 1 节的项目 URL 和 **publishable 公开标识**，点 **保存服务设置**。
3. 点右上角 **登录** 后进入 **注册**，填写自己的邮箱、两次密码，点 **注册并发送验证码**。
4. 在自己的邮箱收到邮件后，把数字填到 **邮件验证码**，点 **验证邮箱并登录**。状态栏应显示邮箱；Supabase 的 **Authentication → Users** 应出现该已验证用户。
5. 以后在 **登录** 页输入邮箱和密码。不勾选“记住登录”时只保持本次进程会话；勾选后仅在此 Windows 用户的凭据管理器中保存刷新令牌，重启联网校验通过后恢复身份。
6. **文件 → 退出登录** 只退出当前会话，不删除当前工程。找回密码需要邮件验证码，成功后重新登录；其他设备的刷新会话会被请求撤销，已经签发的访问令牌仍受原有效期限制。[退出范围说明](https://supabase.com/docs/reference/javascript/auth-signout)

选择该适配器时，正式打包前可把仅含下列两个字段的 `online-auth.json` 放到 `program/lingya.exe` 同目录，首次启动读取。若已保存过本机配置，本机配置优先。发布包的运行清单需重新生成后再分发。当前固定候选默认显示预览，队友也可各自在“账号服务设置”填相同的两个公开值。

```json
{
  "projectUrl": "https://替换为真实项目编号.supabase.co",
  "publishableKey": "替换为sb_publishable_开头的公开标识"
}
```

上面是格式说明，不是可用凭据。SMTP 密钥、数据库密码、访问/刷新令牌都不能添加到这个文件。

## 5. 工程在哪里

联网账号的 **我的文件** 仍使用原本的本地保存/严格打开接口，路径为：

`<本机资料目录>/online/<服务URL的SHA256>/users/<用户UUID去掉短横线>/`

登录后再打开 **文件 → 联网账号** 可以看到实际本机文件区路径。Windows 普通运行的资料目录由 Qt 的 AppLocalDataLocation 决定；测试配置 `LINGYA_PROFILE_ROOT` 时使用其下的 `session`。旧本机账号及 `accounts.json` 保留，入口改为 **文件 → 本机账号（旧）…**，切换前先退出当前账号。

同一个联网账号在另一台电脑登录，能验证同一身份，**不会自动出现原电脑的工程**。转移工程仍需手动复制 `.lingya`；本机分类不是文件加密或 Windows 权限隔离，拥有本机文件权限的人仍可通过资源管理器读取。登录、退出、过期不会替换当前工程或改撤销历史；断网仍可继续编辑与普通本地保存。

## 6. 故障停点与最终集中验证

| 现象 | 处理 |
|---|---|
| 服务配置无效 | 检查默认项目 URL、publishable key；不能填管理密钥、自定义域名或带路径的地址 |
| 没有验证码 | 先查 Supabase Auth 日志、Resend 投递日志、垃圾邮件、已验证发信域和限速；不要通过关闭邮箱验证绕过 |
| 提示过于频繁 | 等控制台规定的间隔；不要连续点注册/重发 |
| 验证码无效 | 使用最近邮件的验证码，过期后重发；确认用了正确模板与邮箱 |
| 网络或证书失败 | 检查电脑时间、项目状态及所处网络能否访问项目；软件不会忽略 TLS 错误或把凭据跟随重定向发送 |
| 记住登录失败 | 本次仍可使用；检查 Windows 凭据管理器可用性，不创建明文令牌文件 |
| 换电脑后“我的文件”为空 | 本版工程不云同步，请复制原电脑的 `.lingya` |

服务端如果启用了 CAPTCHA 或 MFA，本客户端尚无相应交互，不把这种配置宣称为可用；有此要求时需先补对应客户端流程，不能为了绕过已有策略而关闭保护。此次适用于配置后的邮箱密码/邮件验证码流程，保留服务端默认限速；大规模公开开放前另行补反滥用措施。

用户要求统一最终验收，本指南不是逐批催验。外部配置完成后，最终集中检查注册邮件、未验证拒绝登录、错误密码、重启记住、退出、验证码找回、新旧密码、断网和同账号跨机身份；同时保存/重开原工程。当前离线协议测试和本机启动通过也不能代签这些真实服务结果。
