# tst_ui 逐用例超时取证

2026-11-20，适用于 BUG-20261120-001、分支 `fix/a/BUG-20261120-001-ui-timeout-log`。测试注册提交 `6279a5a0076fc7ae53bd4d64c15b9af749375073`，基线 `faeac4b`。甲实现诊断，乙复核测试注册，丙可用同一日志定位。原始超时记录见[PR #56](https://github.com/whosmms/Mind/pull/56)。

`tests/CMakeLists.txt` 将 `tst_ui` 的逐用例输出同时写入标准输出和 `build/<配置>/tests/tst_ui-ctest.txt`。进入用例时立即写出 `entering`。QtTest 每个用例的看门狗为 180 秒，CTest 的整套上限仍为 300 秒。整套超时或 QtTest 启动之前的故障可能由 CTest 先处理。[Qt 6.8.3 QtTest 实现](https://github.com/qt/qtbase/blob/v6.8.3/src/testlib/qtestcase.cpp)

```powershell
./tools/验证环境.ps1 -Configuration Both
ctest --preset release -R '^tst_ui$' --verbose --output-on-failure
Select-String build/release/tests/tst_ui-ctest.txt -Pattern 'entering|QFATAL|Totals:' |
    Select-Object -Last 10
```

现场复现时先保留 `tst_ui-ctest.txt` 与本轮 CTest 输出，再重跑。文件每次覆盖，跨轮先核对写入时间。若本轮未生成新文件，对照 CTest 输出检查 QtTest 启动前的阶段。最后一条 `entering` 是缩小调查范围的证据。

本机使用 Qt 6.8.3、MinGW 13.1.0、CMake 3.30.5、Ninja 1.12.1。冻结 Debug、Release 构建和 CTest 各 29/29 套件通过。逐套件复跑各 595 项通过、0 失败、0 跳过，`tst_ui` 各 122 项。常规 Release `tst_ui` 另连续 4 轮均通过，每轮 122 项，未复现原挂起。[各轮实测数据](../evidence/20261120-甲UI超时取证/validation.json)

以独立 QtTest 进程模拟 `simulatedStall` 阻塞 3 秒。将 QtTest 限时设为 125 毫秒、CTest 限时设为 8 秒时，逐用例文件包含 `QFATAL`。将 CTest 限时设为 1 秒、QtTest 限时设为 180 秒时，CTest 报超时且本轮文件仍有 `entering`。这两个探针故意触发超时，和常规套件计数分开记录。[故意超时日志](../evidence/20261120-甲UI超时取证/timeout-probe.txt)
