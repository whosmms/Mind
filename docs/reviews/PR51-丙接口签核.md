## 1 与乙回执不一致的一处事实（按代码，不照抄）

乙 §7 写「新增 6 个公开方法：`setDraftContext`、`setDraftSupported`、`clearProposal`、`reportApplyResult`、`currentRequestId`、`cancelPending`」。

实际按 `src/ui/AiPanel.h`（`faeac4b`）：

| 成员 | 可见性 | 说明 |
|---|---|---|
| `setDraftContext(request, error = {})` | public | 宿主预填文稿上下文 |
| `setDraftSupported(bool)` | public | 当前类型是否支持文字稿 |
| `reportApplyResult(error)` | public | 采用结果回写状态行 |
| `currentRequestId()` | public | 供 `AiApplyOptions.requestId` |
| `draftPurpose()` | public | 供 `AiCommands::saveDraft` 记录用途 |
| `cancelPending()` | public | 对话框关闭时清挂起 |
| `actionBar()` | public，inline | 把按钮条搬到宿主底部 |
| `clearProposal()` | **private** | 内部状态复位，非公开面 |

即：公开入口是 **7 个**（含 inline `actionBar()`），`clearProposal` 是 private。乙的回执把 private 的 `clearProposal` 计入公开、漏掉 inline 的 `actionBar()`，数量巧合都是 6，但组成不同。本签核以代码为准；不回改乙已发布的回执正文，仅在此登记对照。

## 2 AiPanel 逐条

### 2.1 接受的部分

1. **职责边界没破**：`AiPanel` 仍不持有 `ProjectDocument`、不调 `CommandService`；采用动作走 `applyMapRequested`/`applyDraftRequested` → 宿主 `AiCommands`。与 H-027 定下的「面板只交互、应用由调用方接命令层」一致。
2. **`contextRequested(bool draft)` 的引入是必要的**：文字稿需要「当前工作表 + 选中节点 + 会话修订」三个宿主才知道的值，面板自己拿不到。由面板在发起前发信号、宿主同步回填，比让面板直接读 `ProjectDocument` 干净。
3. **密钥仍不入 QSettings**：`m_rememberKey` 勾选才进 Windows 凭据管理器，走 `SecretStore`；`QSettings` 只存 `ai/model`。符合规范「凭据不放 QSettings」。
4. **`Limits::kAiMapMaxNodes` / `kAiMapMaxDepth` 替换字面量**：原先 `1..200` / `1..6` 与域层上限各写一份，现在单一来源。
5. **旧提案保护**：`onMapReady`/`onDraftReady` 按 `requestId` 丢弃过期响应，`reportApplyResult` 把 `STALE_SOURCE` 之类的错误原文回显，不静默改稿。

### 2.3 复核中排除的怀疑（记录以免下次重查）

- **疑似过期响应过滤失效**：`if (!m_currentRequestId.isEmpty() && requestId != m_currentRequestId) return;` 看着半开。核对 `onGenerateMap` 与 `onGenerateDraft` 均设 `m_currentRequestId`，且 `AiService` 只由本面板发起请求，无第三方 id 通道 → 不成立。
- **疑似 `setBusy(false)` 会误开「采用」**：`onFailed`/`onCanceled` 随后调 `clearProposal()` 把 `m_applyButton` 关回，最终态正确。

## 3 GanttView 逐条

### 3.1 接受的部分

1. **只读**：预览矩形 `setAcceptedMouseButtons(Qt::NoButton)`，不抢命中；日期只在松开后经 `taskDatesEdited` 交给 `TaskCommands::updateTask`，视图仍不写 `ProjectDocument`（铁律 2 未破）。
2. **生命周期干净**：`rebuild()` 在 `target->clear()` **之前**把 `m_dragPreview`/`m_dragItem` 置空，外部刷新（撤销/另存/表格编辑）不会留野指针。与既有 `m_dragItem` 的处理同构。
3. **导出隔离**：role 同时打在矩形和它的子标签上；`MainWindowExport.cpp:64` 按 `kPreviewDataRole` 或 `opacity==0` 排除，导出图不含虚线框。
4. **色板合规**：`QPen(primaryColor(), 1.5, Qt::DashLine)` + `QBrush(mintAccent())` 取自既有色板 helper，未新增颜色（§14）。
5. **语义正确**：`Move` 仍走原「整条位移」，只有 `ResizeStart/ResizeEnd` 才画日期范围虚框——改端才需要告知新范围，整体平移用位移预览更直观。
