## 三、反证

**反证 A（成立）**：把 `locateIssue()` 里的 `showGanttView(outsideFilter)` 改回 `showGanttView(true)`（即 H-034 的行为），
重编 `tst_ui`：`ganttSheetFilterKeepsProjectAndHistory` 在 `tests/tst_ui.cpp:4684` 失败，
`view->tasks().size()` 实际 **3**、期望 **1**。说明「筛选内定位不扩张」这条被用例真实约束。

**反证 B（不成立，暴露测试缺口）**：把 `visibleGanttTasks(false)` 改回 `visibleGanttTasks()`（即沿用上一次的临时全量副本），
同一用例**仍然全绿**（exit 0）。按代码意图这应当失败。

原因不是产品错，而是用例只覆盖了「全量态 → 筛选内任务」这一条路径：此时无论读原筛选还是读临时全量，
目标都判为可见，两种写法结果相同。真正能区分两种写法的是**「全量态下再定位另一个筛选外任务」**：
- 读原筛选（正确）：目标不在筛选内 → 继续保持全量，目标可定位；
- 读临时全量（错误）：目标在全量里 → 误判为可见 → 恢复筛选 → 目标从时间轴消失。

我补了三行探针验证这一点（`locateRequested(otherSheet, task.id)` 连续调用两次，断言 `size()==3` 且 `rowForTask>=0`）：

| 代码 | 探针结果 |
|---|---|
| `visibleGanttTasks()`（错误写法） | 失败：`tst_ui.cpp:4692`，`size()` 实际 **1**、期望 **3**，目标被收起 |
| `visibleGanttTasks(false)`（甲的写法） | 通过 |

所以产品逻辑是对的，缺的是这一条断言。探针已撤，工作树 `git status` 干净，还原后 Debug 全量复跑 24/24 通过。

## 五、登记项（不阻塞）

1. **宽度断言被环境变量条件化**：`tst_ui.cpp` 里 `resize(900,620)` + `QFontMetricsF` 宽度检查写在
   `if (!capture.isEmpty())` 内，只有设了 `LINGYA_GANTT_FEEDBACK_CAPTURE` 才执行；默认 526 回归不校验状态栏是否挤。
   建议把窗口尺寸与字体测量提到 `if` 外，截图保存留在里面。
2. **状态行每次拷贝全量任务**：`updateStatusLine()` 在甘特页会调 `visibleGanttTasks()` 找选中项（最多两次/次刷新），
   `selectTask()` 现在也触发一次；该函数返回值拷贝，任务数百上千时每次选中都拷一份 `QVector<Task>`。
   建议加 `bool isTaskVisibleInGantt(const ID&) const` 只做查找，或缓存可见 id 集合。
3. **可见性判断用的是活动表，不是 `sheetId`**：`locateIssue()` 任务分支没有 `setActiveSheet(sheetId)`，
   却用当前活动表的筛选取 `visibleGanttTasks(false)`。活动表与问题来源表不同时判断依据错位，
   目前偏安全方向（多展开一次全量），不会丢目标，但提示语义会与实际筛选不一致。
4. **清空选中不刷新**：`currentRowChanged` 只在 `index.isValid()` 时调 `selectTask`，用户在任务表点空白/清空选择后
   `m_selectedTaskId` 与「所选任务在筛选外」提示都保留旧值，直到下次刷新。
5. **文案**：「临时全量（甘特图恢复筛选）」是名词加括号入口，原句「问题定位临时显示全部任务；点击视图→甘特图恢复筛选」
   长但可操作。哪个更好交丙做体验判断，我不下结论。
6. **既有问题（本批放大）**：状态行前缀按 `activeSheetId` 判定类型。活动表是思维导图表、经检查助手直接跳进甘特页时，
   前缀仍是「思维导图」，与当前页不符。H-034 之前就有，提示变长后更显眼。
7. **切表复位仍靠三条路径**：甘特菜单、活动表变更、`loadNewDocument` 都在；节点定位路径（非任务）不复位
   `m_ganttTaskLocation`，与 H-034 时一致，未扩大范围。
